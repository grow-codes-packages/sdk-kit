# AGENTS.md — sdk-kit

Instructions for AI coding agents and humans working on sdk-kit. `CLAUDE.md` is a symlink to this
file.

## What lives here

| Path | What | Notes |
| - | - | - |
| `spec/SPEC.md` | the SDK contract for all 17 service repositories | changed only by the epic coordinator |
| `spec/services.json` | the service catalog (token values) | same |
| `conformance/` | conformance scenarios + `core-unit.md` | same; copied verbatim into every repo |
| `template/common/` | repository-level files (README, LICENSE, NOTICE, AGENTS, Makefile, workflows, docker harness, docs) | |
| `template/<lang>/` | language packages: `typescript rust go python java` | each has a `template.json` |
| `template/docker/` | `Dockerfile.<lang>` | |

| `sdk_kit/` | the generator (`sdk-kit new / sync / list / check`) | Python ≥ 3.10, stdlib only at runtime |
| `tests/` | pytest suite of the generator | ≥ 90 % lines and branches |
| `demo/` | demo server for `sdk-kit new demo` | |
| `skills/sdk-kit/SKILL.md` | how an agent uses sdk-kit | |

## Rules

- **The spec is the contract.** Template code follows `spec/SPEC.md` exactly (names, defaults,
  error codes, env rules). Do not edit `spec/` or `conformance/` unless you are the coordinator; note
  questions instead.
- **API parity.** A change to the public API of the template lands in all five languages at once.
- **Template files that sdk-kit owns** start with the header
  `Generated by sdk-kit __SDK_KIT_VERSION__ — do not edit; change sdk-kit and run "sdk-kit sync"`
  in the file's comment syntax, within the first 10 lines. `sdk-kit sync` only ever overwrites
  files with this header. Files without it (README, NOTICE, LICENSE, release-please files, the
  skill, the client/config skeletons) are generated once and then belong to the service.
- **Tokens**: use only the SPEC §0 tokens (plus `__ENV__` in docs). `sdk-kit check` fails a repo
  that still contains one. Category-specific content goes into category folders (path rule) or
  `@sdk-kit:if` blocks; list paths that do not follow the segment rule in `template.json`.
- **No build output in `template/`**; the generator skips the usual folders but keep it clean.
- **Generated repos** must pass `sdk-kit check`, and every language must compile, lint clean and
  pass its coverage gate for all categories together and for each single category.

## Commands

```sh
make test        # generator tests + coverage gate (lines and branches >= 90 %)
make lint        # ruff + mypy --strict
make demo        # bin/sdk-kit new demo --dest build/demo --force
make check-all   # render all services, run sdk-kit check on each
bin/sdk-kit new openbao --dest build/openbao --force
```

Language templates are tested by rendering them (`make demo` or `bin/sdk-kit new <key>`) and running
`make lint coverage` inside the rendered language folder.

## Shared dev server limits

`CARGO_BUILD_JOBS=4`, Maven `-T 1`, `GOFLAGS=-p=4`, `vitest --maxWorkers=2`. Docker suites only through
`flock ~/grow/.artifcats/locks/sdk-docker-<1..4>.lock` (the generated root `Makefile` does this when
the directory exists), unique Compose project names, no host ports, always `docker compose down -v`.

## Releases

sdk-kit itself is versioned in `sdk_kit/__init__.py` (`__version__`); generated repositories record
it in `.sdk-kit.json` and in the generated-file headers. Service repositories pin the reusable
workflows of this repository by tag.
