# sdk-kit

sdk-kit turns `template/` into one repository per service (17 in `spec/services.json`, plus `demo`)
with the same API in TypeScript, Rust, Go, Python and Java. The contract is `spec/SPEC.md`.

## Generate a repository

```sh
bin/sdk-kit list                                  # keys, categories, images
bin/sdk-kit new openbao --dest ../openbao         # refuses a non-empty dir; --force to overwrite
bin/sdk-kit new demo --dest /tmp/demo             # demo service, all categories
bin/sdk-kit new my-svc --service-json svc.json    # not in the catalog (same fields as services.json)
bin/sdk-kit check --dest ../openbao               # must print "check passed"
```

Then in the new repo: `make build lint coverage`, and `make test-docker LANGS=<lang>` for the
integration suite.

## Update a repository after a template change

```sh
sdk-kit sync --dest ../openbao --dry-run   # preview
sdk-kit sync --dest ../openbao             # exit 1 when locally modified files were skipped
sdk-kit sync --dest ../openbao --force     # overwrite local edits of generated files
```

Sync overwrites only files with the `Generated by sdk-kit` header plus `conformance/`. It never
touches service-owned files. A generated file whose header was deleted is treated as service-owned.
When the template starts generating a file that the repository has as a header-less copy, sync
takes it over (`adopt`) only if the copy is unchanged since sdk-kit wrote it (same hash as recorded);
an edited copy stays service-owned.
Inside a generated file, the body of every **keep region** (`@sdk-kit:keep <name>` …
`@sdk-kit:endkeep`) belongs to the service: sync keeps it, and the SHA-256 in `.sdk-kit.json` is
taken without region bodies, so editing one never counts as a local modification. A region with
content that the new template no longer has blocks the sync of that file (`SKIPPED (keep region …)`,
exit 1) until it is moved or `--force` drops it. A file generated before the template had regions
gets the template's default bodies on its first sync, but only when it is unmodified; a locally
modified file is skipped as before.

## Which files may be edited in a service repository?

- Header `Generated by sdk-kit … — do not edit` in the first lines → change it in sdk-kit's
  `template/`, then `sdk-kit sync`.
- Between `@sdk-kit:keep <name>` and `@sdk-kit:endkeep` in a generated file → edit in the repo
  (service settings and examples in `docs/configuration.md` / `docs/client.md`, service sections of
  `docs/troubleshooting.md` and `AGENTS.md`, service dependencies and plugins in `java/pom.xml`).
  Never edit, move or remove the marker lines themselves.
- No header (README, NOTICE, skill, client/config, service modules, examples) → edit in the repo.

## Rules for service code that uses the template

- Vendor error remapping uses the transport hook, so `on_error` hooks see the mapped error: TS
  `classifyError`, Rust `HttpTransport::with_error_mapper` / `RequestBuilder::map_error`, Go
  `setErrorMapper` / `request.MapError`, Python `error_mapper`, Java `TransportConfig.errorMapper`.
- Rust services keep `cargo clippy --lib --no-default-features -- -D warnings` clean (generated
  `rust/Makefile` lint). Their own gRPC exporters take TLS from
  `tracing::apply_grpc_tls(builder, endpoint, &TlsConfig)` (works with and without the `otlp-tls`
  feature; `https` without it → `CONFIG`) instead of own `#[cfg(feature = "otlp-tls")]` TLS code.
- Service additions to generated files go into their keep regions (see above), never outside.

## Editing the template

- Tokens (contents and paths): `__KEY__ __KEY_SNAKE__ __KEY_UPPER__ __PKG__ __SERVICE__
  __SERVICE_LOWER__ __DISPLAY__ __VENDOR__ __UPSTREAM_LICENSE__ __IMAGE__ __PORT__ __VERSION__
  __SDK_KIT_VERSION__ __CATEGORIES__` (+ `__ENV__` for docs). `GROW___KEY_UPPER___URL` becomes
  `GROW_OPENBAO_URL`.
- Category blocks, any comment style, no nesting:

  ```
  // @sdk-kit:if logging
  ...
  // @sdk-kit:endif
  # @sdk-kit:if any(logging,tracing)
  <!-- @sdk-kit:if secrets -->
  ```

- Keep regions (service-owned part of a generated file; the marker lines stay in the output, text
  after the name is a description, names `[A-Za-z0-9][A-Za-z0-9_.-]*` unique per file, no nesting,
  put explanations outside the region, keep blank lines around markers in Markdown):

  ```
  <!-- @sdk-kit:keep service-settings -->
  default body for new repositories
  <!-- @sdk-kit:endkeep -->
  ```

  Renaming or removing a region makes sync skip every repository that has content in it; add a
  new region instead. `sdk-kit check` reports broken markers in generated files.
- Category paths: a segment matching `^_?(secrets|logging|tracing)([_.-]|$)` (`src/logging/`,
  `secrets_cache.go`, `_tracing/`); others go into `template/<lang>/template.json`
  (`{"categories": {"logging": ["zapadapter"]}}`).
- Put the generated header at the top of every file sdk-kit should keep in sync.
- Verify: `make test` (generator), `make check-all` (all services), and lint/coverage inside a
  rendered language folder for all categories and each single category.
