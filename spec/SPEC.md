# Grow Codes SDK specification (sdk-kit spec v0.1.0)

This is the single contract for every package in `grow-codes-packages`. All 17 service repos
(`spec/services.json`) ship the same API in **TypeScript, Rust, Go, Python and Java**. Only the epic
coordinator (GRO-1364) changes this file. If you need a change, ask; never let one language drift.

Notation below is TypeScript-like camelCase. Section 1 gives the per-language naming rules.

---

## 0. Template tokens and generated code

`sdk-kit new <key>` copies `template/common/**` and `template/<lang>/**` into a new repo and replaces
these tokens in file **contents and paths** (values come from `spec/services.json`):

| Token | Example (`hashicorp-vault`) | Meaning |
| - | - | - |
| `__KEY__` | `hashicorp-vault` | catalog key = repo name |
| `__KEY_SNAKE__` | `hashicorp_vault` | key with `_` |
| `__KEY_UPPER__` | `HASHICORP_VAULT` | env-var infix: `GROW___KEY_UPPER___URL` → `GROW_HASHICORP_VAULT_URL` |
| `__PKG__` | `vault` | Go package name, Java package leaf (`codes.grow.packages.__PKG__`) |
| `__SERVICE__` | `Vault` | PascalCase type prefix: `VaultClient`, `VaultConfig`, `VaultError` |
| `__SERVICE_LOWER__` | `vault` | camelCase of `__SERVICE__` (variable names) |
| `__DISPLAY__` | `HashiCorp Vault` | product name for docs |
| `__VENDOR__` | `HashiCorp, Inc. (an IBM company)` | trademark owner (NOTICE) |
| `__UPSTREAM_LICENSE__` | `BUSL-1.1 …` | upstream licence text for docs |
| `__IMAGE__` / `__PORT__` | `hashicorp/vault:2.2.2` / `8200` | Docker image + port from the stack catalog |
| `__VERSION__` | `0.1.0` | initial package version |
| `__SDK_KIT_VERSION__` | `0.1.0` | sdk-kit version the repo was generated from |
| `__CATEGORIES__` | `secrets` | comma list |

**Category blocks.** Lines between `@sdk-kit:if <category>` and `@sdk-kit:endif` markers (in any
comment syntax: `// @sdk-kit:if logging`, `# @sdk-kit:if logging`, `<!-- @sdk-kit:if logging -->`)
are kept only when the service has that category; the marker lines are always removed. Blocks do not
nest. `@sdk-kit:if any(logging,tracing)` is also allowed.

**Category paths.** A path belongs to a category when any path segment matches
`^_?(secrets|logging|tracing)([_.-]|$)` (e.g. `src/logging/`, `logging_batch.go`, `_tracing/`,
`secrets-ops.ts`, `LoggingAppenderTest.java` does **not** match — use folders). Paths that do not
follow the rule (e.g. Go `zapadapter/`) are listed in `template/<lang>/template.json`:
`{"categories": {"logging": ["zapadapter"], "tracing": ["grpcadapter"]}}`. The generator drops a
category's paths when the service does not have that category.

**Generated vs owned files.** Files under the core and category folders start with the header
`Generated by sdk-kit __SDK_KIT_VERSION__ — do not edit; change sdk-kit and run "sdk-kit sync"`
(in the language's comment syntax). Service code lives outside those folders and is owned by the
service repo.

Repo layout produced by the generator:

```
<key>/
  typescript/  rust/  go/  python/  java/
  docker/compose.yml  docker/Dockerfile.{typescript,rust,go,python,java}  docker/bootstrap/
  conformance/        (scenarios copied from sdk-kit, pinned version in conformance/VERSION)
  examples/{typescript,rust,go,python,java}/
  docs/ + mkdocs.yml
  skills/<key>-sdk/SKILL.md  AGENTS.md  CLAUDE.md -> AGENTS.md
  README.md LICENSE NOTICE SECURITY.md CONTRIBUTING.md CODE_OF_CONDUCT.md Makefile
  .github/workflows/{ci,release,docs}.yml
  release-please-config.json .release-please-manifest.json
```

Root `Makefile` targets: `build`, `lint`, `test` (unit), `coverage`, `test-docker` (all languages;
`make test-docker LANGS="go python"` for a subset), `docs`, `clean`. Each language folder has its own
`Makefile` with `build lint test coverage clean`; the root delegates.

## 2. Shared core (identical in all 17 repos)

### 2.1 Errors

Base error `<Service>Error` (Go: `*Error`; Rust: `enum Error` with `code()`), fields:

| Field | Type | Meaning |
| - | - | - |
| `code` | `ErrorCode` | canonical code below |
| `message` | string | human text; **never** contains secrets, tokens, request bodies or unfiltered response bodies |
| `httpStatus` | int? | HTTP status when the error came from a response |
| `requestId` | string? | vendor request id header when present (`x-request-id`, `x-amzn-requestid`, `x-datadog-request-id`, …) |
| `retryable` | bool | whether retrying the same call may succeed |
| `cause` | error? | underlying error (redacted) |

| `ErrorCode` (wire value) | Subclass / variant | Typical source | retryable |
| - | - | - | - |
| `CONFIG` | `ConfigError` | invalid or missing configuration | false |
| `AUTHENTICATION` | `AuthenticationError` | HTTP 401 | false |
| `PERMISSION_DENIED` | `PermissionDeniedError` | HTTP 403 | false |
| `NOT_FOUND` | `NotFoundError` | HTTP 404, missing record | false |
| `CONFLICT` | `ConflictError` | HTTP 409, 412, CAS mismatch | false |
| `RATE_LIMITED` | `RateLimitError` (+ `retryAfter` duration?) | HTTP 429 | true |
| `VALIDATION` | `ValidationError` | HTTP 400, 413, 422, other 4xx, bad input caught client side | false |
| `UNAVAILABLE` | `UnavailableError` | network error, DNS, connection refused/reset, HTTP 500, 502, 503 | true |
| `TIMEOUT` | `TimeoutError` | connect/request/total deadline exceeded, HTTP 408, 504 | true |
| `UNSUPPORTED` | `UnsupportedError` | capability the service/deployment does not offer (HTTP 501, missing API, enterprise-only) | false |
| `CANCELLED` | `CancelledError` | caller cancelled (AbortSignal, ctx cancel, task cancel, future cancel) | false |

Go: `type Error struct{ Code ErrorCode; Message string; HTTPStatus int; RequestID string; Retryable bool; RetryAfter time.Duration; Err error }`,
sentinels `ErrConfig, ErrAuthentication, ErrPermissionDenied, ErrNotFound, ErrConflict, ErrRateLimited, ErrValidation, ErrUnavailable, ErrTimeout, ErrUnsupported, ErrCancelled`
so `errors.Is(err, openbao.ErrNotFound)` works (`(*Error).Is` compares codes). Context cancellation maps to `ErrCancelled`, deadline to `ErrTimeout`, and `errors.Is(err, context.Canceled)` also stays true via `Unwrap`.
Rust: `#[non_exhaustive] pub enum Error { Config{..}, Authentication{..}, … }` built with `thiserror`, plus `fn code(&self) -> ErrorCode`, `http_status()`, `request_id()`, `is_retryable()`; `pub type Result<T> = std::result::Result<T, Error>`.
Python: `<Service>Error(Exception)` with subclasses; attributes `code`, `http_status`, `request_id`, `retryable`, `retry_after`.
Java (Java convention: `…Exception` instead of `…Error`): `<Service>Exception extends RuntimeException` (unchecked) with subclasses `ConfigException`, `AuthenticationException`, `PermissionDeniedException`, `NotFoundException`, `ConflictException`, `RateLimitException`, `ValidationException`, `UnavailableException`, `TimeoutException` (name clash with `java.util.concurrent.TimeoutException` is intentional; it lives in the SDK package), `UnsupportedException`, `CancelledException`. Getters `code()`, `httpStatus()` (`OptionalInt`), `requestId()` (`Optional<String>`), `retryable()`, `retryAfter()`.
TypeScript: `class <Service>Error extends Error` with subclasses as in the table; `err.code`, `err.httpStatus?`, `err.requestId?`, `err.retryable`, `err.retryAfterMs?`, `err.cause?`.

Error message format: `"<operation>: <short reason> (HTTP <status>)"`, e.g. `"kv.read secret/app: not found (HTTP 404)"`.
Vendor error text extracted from the response body is redacted (section 2.6) and truncated to 300 characters.

### 2.2 Configuration

`<Service>Config` is immutable after construction (TS `Object.freeze`, Rust owned struct built by
`<Service>ConfigBuilder`, Go value type built by `NewConfig(opts...)`/struct literal + `Validate()`,
Python `@dataclass(frozen=True)`, Java final class with builder). Common fields (service configs add
their own, e.g. `token`, `namespace`, `org`, `stream`):

| Field | Default | Env (after `GROW_<KEY_UPPER>_` prefix) |
| - | - | - |
| `url` (endpoint base URL) | service default (e.g. `http://127.0.0.1:8200`) | `URL` |
| `connectTimeout` | 10 s | `CONNECT_TIMEOUT` |
| `requestTimeout` (per attempt) | 30 s | `REQUEST_TIMEOUT` |
| `totalTimeout` (whole call incl. retries) | 120 s | `TOTAL_TIMEOUT` |
| `retry` (`RetryPolicy`) | see 2.3 | `MAX_RETRIES` |
| `tls.caCertPath` / `tls.caCertPem` | none | `CA_CERT` (path) |
| `tls.clientCertPath` + `tls.clientKeyPath` | none | `CLIENT_CERT`, `CLIENT_KEY` |
| `tls.insecureSkipVerify` | false (tests only; logs a warning once) | `INSECURE_SKIP_VERIFY` |
| `proxy` (URL) | none — environment proxies are **ignored** unless set here | `PROXY` |
| `headers` (extra request headers) | `{}` | — |
| `userAgentSuffix` | none (appended after the standard UA) | — |
| `hooks` (2.5) | none | — |
| `logger` (2.5) | silent | — |

`<Service>Config.fromEnv(overrides?)` precedence: **explicit value > `GROW_<KEY_UPPER>_<NAME>` >
vendor variables (in the order listed in the service ticket, e.g. `BAO_ADDR` then `VAULT_ADDR`) >
default.** A present but invalid value raises `ConfigError` whose message names the variable but never
its value. Parsing rules: durations accept integer milliseconds (`1500`) or Go-style units
(`500ms`, `10s`, `2m`, `1h`, combinations `1m30s`); booleans accept `true/false/1/0/yes/no/on/off`
(case-insensitive); empty string = unset. `validate()` checks URL scheme (`http`/`https`), positive
timeouts, `maxRetries >= 0`, client cert and key given together, and service rules; it raises
`ConfigError`. `toString()`/debug output redacts every credential field.

The env helper (`EnvReader` in core) is shared code: `string(name, vendorNames[])`, `duration(...)`,
`bool(...)`, `int(...)`, each returning "unset" when no variable is present. It takes an injectable
env map so tests never touch the real process environment.

### 2.3 Transport, retries, timeouts

One internal `HttpTransport` per client (TS: `fetch` with an undici `Agent`/`ProxyAgent` dispatcher for
TLS/proxy; Rust: `reqwest` with `rustls-tls`, `default-features = false`; Go: `net/http` with a custom
`Transport`; Python: `httpx.Client`/`httpx.AsyncClient` with `trust_env=False`; Java:
`java.net.http.HttpClient`). Responsibilities:

- Base URL join, query encoding, JSON encode/decode, default headers, `User-Agent:
  grow-codes-<key>/<version> (<language>)` where `<language>` is `typescript|rust|go|python|java`
  (plus ` <userAgentSuffix>` when set).
- **RetryPolicy** defaults: `maxRetries = 3` (so up to 4 attempts), `initialBackoff = 100 ms`,
  `maxBackoff = 10 s`, `multiplier = 2`, `maxRetryAfter = 60 s`. Backoff for retry *n* (0-based) is
  **full jitter**: `random(0, min(maxBackoff, initialBackoff * multiplier^n))`. The random source is
  injectable for tests.
- **Retry when:** HTTP 429, 502, 503, 504, 408; network/connection errors; for **idempotent**
  requests also HTTP 500. Idempotent = `GET HEAD OPTIONS PUT DELETE` or the request is explicitly
  marked idempotent. Non-idempotent requests (e.g. `POST`) are retried only on 429 and on connection
  errors that happened before the request was sent (connect refused/DNS), never after an uncertain
  send.
- **Retry-After:** on 429/503 parse `Retry-After` as seconds or HTTP-date; wait `max(retryAfter,
  backoff)`. If the wait exceeds `maxRetryAfter` or the remaining `totalTimeout`, stop and raise
  `RateLimitError`/`UnavailableError` with `retryAfter` set.
- **Timeouts:** `connectTimeout` for connection setup, `requestTimeout` per attempt (headers + body),
  `totalTimeout` for the whole call including backoff sleeps. Exhausted → `TimeoutError`.
- **Cancellation:** honoured during the request and during backoff sleeps → `CancelledError`.
- Status mapping per 2.1 when retries are exhausted or the status is not retryable.
- Every attempt calls hooks (2.5). Retries are counted in hook data (`attempt`, starting at 1).

### 2.4 Client surface (every service)

```
class <Service>Client {
  constructor(config: <Service>Config)            // Rust: <Service>Client::new(config)?; Go: NewClient(cfg) (*Client, error); Python: <Service>Client(config) or <Service>Client.from_env(); Java: <Service>Client.create(config) / builder()
  static fromEnv(): <Service>Client
  health(): Promise<HealthStatus>                 // unauthenticated liveness/readiness
  ping(): Promise<number /*latencyMs*/>           // authenticated round trip; AuthenticationError on bad credentials
  serverVersion(): Promise<string>                // UnsupportedError when the service exposes none
  close(): Promise<void>                          // idempotent; flushes batch processors, stops renewers/watchers
}
HealthStatus { healthy: boolean; status: string /* "ok" | "degraded" | "unhealthy" | "unreachable" | vendor word */; details: Record<string, string> }
```

`health()` never throws for an unhealthy or unreachable service: it returns `healthy=false` with
`status="unreachable"` on network errors and the vendor's word otherwise. It throws only for
`CANCELLED` and `CONFIG`. Service-specific modules hang off the client as properties/accessors
(`client.kv`, `client.transit()`, Go `client.KV()`), defined in each service ticket.

### 2.5 Hooks and logger

```
Hooks {
  onRequest?(info: RequestInfo): void      // RequestInfo  { method, url, headers, attempt }
  onResponse?(info: ResponseInfo): void    // ResponseInfo { method, url, status, durationMs, attempt, requestId? }
  onError?(info: ErrorInfo): void          // ErrorInfo    { method, url, error, attempt, willRetry }
}
Logger { debug(msg, fields?), info(msg, fields?), warn(msg, fields?), error(msg, fields?) }
```

`url` has redacted query values; `headers` are redacted (2.6). Exceptions thrown by hooks or the
logger are caught and ignored. The default logger is silent. Python's default is a
`logging.getLogger("grow_<key>")` with a `NullHandler`; Java's default is no-op (no SLF4J
dependency in core); Rust uses the `tracing` crate at `debug` level only when the user installs a
subscriber; Go uses a `*slog.Logger` that discards.

### 2.6 Redaction and secret types

- `REDACTED = "[REDACTED]"`.
- Sensitive **header names** (case-insensitive): `authorization`, `proxy-authorization`, `cookie`,
  `set-cookie`, and any name containing `token`, `secret`, `password`, `api-key`, `apikey`, `key`
  (except `content-type`-like names that merely end in "key" are still redacted — prefer safety),
  `auth`, `session`, `signature`, `credential`.
- Sensitive **field/query names** (case-insensitive substring): `password`, `passwd`, `secret`,
  `token`, `authorization`, `cookie`, `api_key`, `apikey`, `api-key`, `access_key`, `private_key`,
  `client_secret`, `credential`, `session`, `signature`.
- `redactHeaders(map)`, `redactUrl(url)`, `redactFields(map, extraKeys?)` (recursive into nested
  maps/lists), `redactText(text, knownSecrets[])` (replaces every known secret value of length ≥ 4).
- `Secret`/`SecretString` type wraps credentials in config: `toString`/debug/JSON →
  `[REDACTED]`; `reveal()` returns the value. Rust: `secrecy`-style own type implementing
  `Zeroize` + `ZeroizeOnDrop` (`zeroize` crate) with `expose_secret()`/`reveal()`. Java:
  `char[]`-backed with `clear()`. Every error message passes through `redactText` with the client's
  known secrets.

## 3. Category: Secrets

Template provides `SecretValue`, `SecretMetadata`, `SecretsProvider` interface, an abstract
`BaseSecretsProvider` that implements everything from five primitives, `SecretCache`, `watch`, and
`loadEnv`. Services implement the primitives on top of their API.

```
SecretValue {                        // redacting wrapper
  reveal(): string                   // UTF-8 text (throws ValidationError for non-UTF-8 binary)
  revealBytes(): Uint8Array
  json<T>(): T                       // ValidationError if not JSON
  version?: string                   // opaque version string (KV "3", AWS VersionId, Infisical version)
  toString() → "SecretValue([REDACTED])"
}
SecretMetadata { name: string; path?: string; version?: string; createdAt?: Date; updatedAt?: Date;
                 tags: Record<string,string>; versions?: number; extra: Record<string,string> }
GetOptions    { version?: string; path?: string }
SetOptions    { path?: string; cas?: number; tags?: Record<string,string>; description?: string }
DeleteOptions { path?: string; versions?: string[]; permanent?: boolean }

interface SecretsProvider {
  get(name, opts?): SecretValue | null           // null when missing
  getString(name, opts?): string | null
  getJson<T>(name, opts?): T | null
  getNumber(name, opts?): number | null           // ValidationError if not a number
  getBool(name, opts?): boolean | null            // true/false/1/0/yes/no/on/off, else ValidationError
  require(name, opts?): SecretValue               // NotFoundError when missing
  exists(name, opts?): boolean
  getMany(names[], opts?): Map<string, SecretValue>   // missing names omitted; order = request order
  getAll(path?): Map<string, SecretValue>         // every secret directly under path (non-recursive)
  list(prefixOrPath?): SecretMetadata[]           // names + metadata, sorted by name
  set(name, value: string | Uint8Array | object, opts?): string   // returns new version ("" if the service has no versions); objects are JSON-encoded
  delete(name, opts?): void                       // NotFoundError if missing
  metadata(name, opts?): SecretMetadata | null
  loadEnv(source: string /*path*/ | Record<envName, secretName>, opts?: { override?: false; prefix?: "" }): Record<string, string /*envName→secretName*/>
  watch(name, intervalMs, onChange: (newValue: SecretValue|null, oldValue: SecretValue|null) => void, opts?: { onError? }): WatchHandle  // WatchHandle.stop()
}

abstract class BaseSecretsProvider implements SecretsProvider {   // primitives a service implements:
  protected abstract fetchSecret(name, opts): SecretValue | null
  protected abstract listSecrets(path?): SecretMetadata[]
  protected abstract putSecret(name, bytes, opts): string
  protected abstract removeSecret(name, opts): void            // throw NotFoundError when missing
  protected abstract fetchMetadata(name, opts): SecretMetadata | null
}
```

- `loadEnv(path)` sets one variable per secret directly under `path`; the variable name is the secret
  name upper-cased with every non `[A-Z0-9_]` character replaced by `_`, prefixed by `prefix`.
  `loadEnv(mapping)` sets each `envName` from its secret (missing → `NotFoundError`). Existing
  variables are kept unless `override=true`. Returns the variables set (names only, never values).
  Process environment targets: TS `process.env`; Rust `std::env::set_var` (edition 2021); Go
  `os.Setenv`; Python `os.environ`; Java cannot change the environment, so it sets **system
  properties** and returns the map (documented).
- `watch` polls every interval, compares `version` (or SHA-256 of the value when no version), calls
  `onChange` on change including deletion (`newValue=null`); errors go to `opts.onError` and polling
  continues. `stop()` is idempotent; `close()` of the client stops all watchers.
- `SecretCache(provider, { ttlMs = 60000, maxEntries = 1000, refreshAheadFactor = 0.8,
  staleWhileRevalidateMs = 0, clock? })` implements `SecretsProvider` reads (`get*`, `require`,
  `exists`, `getMany`) with LRU eviction; writes pass through and invalidate. Refresh-ahead: a hit
  after `ttl * refreshAheadFactor` triggers one background refresh. Stale-while-revalidate: within
  `ttl + staleWhileRevalidate` a stale value is returned while one refresh runs. Negative results
  (`null`) are cached for the same TTL. `invalidate(name)`, `clear()`, `stats(): { hits, misses,
  evictions, refreshes, size }`. The clock is injectable.

## 4. Category: Logging

```
enum Severity { Trace = 1, Debug = 5, Info = 9, Warn = 13, Error = 17, Fatal = 21 }   // OTel severity numbers
LogRecord {
  timestamp: Date; observedTimestamp?: Date;
  severity: Severity; severityText: string /* "TRACE".."FATAL" or vendor text */;
  body: string;                                  // message; structured bodies are JSON-encoded strings
  attributes: Record<string, AttrValue>;         // AttrValue = string | number | boolean | AttrValue[] | Record<string, AttrValue>
  resource: Record<string, AttrValue>;           // service.name, service.version, deployment.environment, host.name
  traceId?: string /* 32 lower-hex */; spanId?: string /* 16 lower-hex */; traceFlags?: number;
}
ExportResult { accepted: number; rejected: number; error?: <Service>Error }

interface LogExporter {                           // a service implements this
  export(records: LogRecord[], opts: { signal?, gzip: boolean }): Promise<ExportResult>
  shutdown(): Promise<void>
}

BatchOptions {
  maxQueueSize = 2048; maxBatchSize = 512; maxBatchBytes = 1_048_576;   // bytes = UTF-8 JSON size of the records
  flushIntervalMs = 1000; exportTimeoutMs = 30000;
  dropPolicy: "drop_newest" (default) | "drop_oldest" | "block";
  gzip = true;
  onDrop?(records, reason: "queue_full" | "shutdown" | "export_failed"); onError?(error, records);
}
BatchStats { queued, sent, dropped, failed, retries }

class BatchProcessor {                            // generic; owns a background worker (TS timer, Rust tokio task, Go goroutine, Python thread / asyncio task, Java scheduled executor)
  constructor(exporter: LogExporter, opts?: BatchOptions)
  add(record): boolean                            // false when dropped; never blocks unless dropPolicy=block
  flush(timeoutMs?): Promise<void>                // exports everything queued now
  shutdown(timeoutMs?): Promise<void>             // drains then stops; idempotent; later add() → dropped("shutdown")
  stats(): BatchStats
}

interface LogClient {
  send(record: LogRecord | LogInput): void        // enqueue (applies RedactionProcessor + defaults: timestamp=now, resource from config)
  sendBatch(records: (LogRecord | LogInput)[]): void
  flush(timeoutMs?): Promise<void>
  close(): Promise<void>                          // flush + shutdown, idempotent
  stats(): BatchStats
  logger(name?: string, attributes?): Logger      // facade below
}
LogInput { message: string; severity?: Severity = Info; attributes?; timestamp?; traceId?; spanId? }

class Logger {
  trace|debug|info|warn|error|fatal(message: string, attributes?: Record<string, AttrValue>): void
  child(attributes): Logger
  // minSeverity option (default Info); trace correlation: when an OpenTelemetry span is active and the
  // record has no traceId, traceId/spanId/traceFlags are taken from the active span context.
}

class RedactionProcessor {
  constructor({ keys = DEFAULT_REDACT_KEYS, patterns: RegExp[] = [], replacement = "[REDACTED]" })
  process(record): LogRecord                      // returns a redacted copy; keys match attribute names case-insensitively (substring), recursively; patterns apply to body and string attribute values
}
DEFAULT_REDACT_KEYS = ["password", "passwd", "token", "authorization", "secret", "cookie", "api_key", "apikey", "access_key", "private_key"]

interface LogQueryClient {                        // when the service has a query API; otherwise methods throw UnsupportedError
  search(query: string, opts?: { start?: Date; end?: Date; limit?: 100; order?: "desc" | "asc"; cursor? }): Promise<LogSearchResult>
  tail(query, onRecord, opts?): TailHandle        // UnsupportedError if the service cannot stream or poll
  listStreams(): Promise<string[]>
  listLabels(): Promise<string[]>
  waitForLog(query, opts?: { timeoutMs = 30000; intervalMs = 1000; predicate?(r): boolean }): Promise<LogRecord>  // template helper on top of search(); TimeoutError when nothing matches
}
LogSearchResult { records: LogRecord[]; nextCursor?: string; total?: number }
```

Template provides: `Severity`, `LogRecord`, `LogInput`, `BatchProcessor`, `BatchingLogClient`
(implements `LogClient` from a `LogExporter` + options + resource + redaction), `Logger`,
`RedactionProcessor`, `waitForLog` helper (`pollUntil` generic), JSON (de)serialisation of
`LogRecord` to the normalized wire form (`spec/schemas/log-record.schema.json`), and the framework
adapters, each taking a `LogClient`:

| Language | Adapters (template) |

## 6. Conformance suite

Scenarios live in `conformance/scenarios/*.json` (copied into every repo; version in
`conformance/VERSION`). Each language template contains a **runner** that executes the scenarios of
the selected categories against factory functions supplied by the service package's integration
test: `secrets → SecretsProvider`, `logging → { client: LogClient, query: LogQueryClient | null }`,
`tracing → { handle: TracingHandle, query: TraceQueryClient | null }`, `core → <Service>Client`.
Format (`spec/schemas/scenario.schema.json`):

```json
{
  "id": "secrets.roundtrip",
  "category": "secrets",
  "description": "set → get → list → metadata → delete",
  "requires": ["write"],
  "steps": [
    { "op": "set", "args": { "name": "${prefix}alpha", "value": "s3cr3t-${run}" }, "save": "v1" },
    { "op": "get", "args": { "name": "${prefix}alpha" }, "expect": { "reveal": "s3cr3t-${run}" } },
    { "op": "get", "args": { "name": "${prefix}missing" }, "expect": { "null": true } },
    { "op": "require", "args": { "name": "${prefix}missing" }, "expect": { "error": "NOT_FOUND" } }
  ]
}
```

- Variables: `${run}` random 8-char lowercase id per scenario run, `${prefix}` = the provider prefix
  supplied by the service test (default `grow-conformance/${run}/`), `${<saveName>}` = value saved
  by an earlier step's `save`.
- `requires`: capabilities the target must declare (`write`, `versions`, `delete`, `query`, `tail`,
  `dependencies`, `labels`, `streams`); the runner **skips** (and reports) scenarios whose
  requirements the service test does not declare. Skips must be justified in the service docs.
- Expectations: `reveal` (string equality of `SecretValue.reveal()`), `equals` (deep JSON
  equality), `null: true`, `notNull: true`, `true`/`false`, `error: "<ErrorCode>"`, `contains`
  (array contains / string contains), `notContains`, `count`, `minCount`, `sorted: true`,
  `type: "string"|"number"|"boolean"|"object"|"array"`, `stringForm: { notContains | contains }`
  (applies to the language's `toString`/debug/JSON-serialised form of the result — the redaction
  check), `tree: { parentName: [childNames…] }` (span parent/child relation by name).
  `equals` with an object compares only the listed keys (subset match) — `{ "healthy": true }`
  matches a full `HealthStatus`.
- A step may carry its own `requires` (skipped alone when missing). A scenario may carry
  `batchOptions` (logging) that the factory applies when it builds the `LogClient`.
- More variables: `${serviceName}` (the tracing service name the factory configured); inside
  `sendBatch` with `count`, `#{i}` is replaced by the record index (0-based).
- Results of ops: `get`/`require` → `SecretValue`; `getMany`/`getAll` → map (count = entries);
  `list` → array of metadata (sorted = by name); `loadEnv` → map of env names; `searchUntil` →
  array of `LogRecord` (polls `search` until `minCount` or timeout); `stats` → `BatchStats`;
  `span` → the root trace id (string); `getTraceUntil` → `Trace` (count = spans); `health` →
  `HealthStatus`; `ping` → latency number.
- Ops — **secrets:** `set get getString getJson getNumber getBool require exists getMany getAll list
  delete metadata loadEnv`; **logging:** `send sendBatch flush searchUntil(query, minCount,
  timeoutMs)`, `stats`; **tracing:** `span(name, attributes, children[])` (creates a span tree),
  `flush`, `getTraceUntil(traceIdRef, minSpans, timeoutMs)`, `listServices`; **core:** `health ping
  serverVersion close`.
- Unit-level conformance (retry with Retry-After, redaction in error text, timeouts, close twice) is
  covered by template unit tests named after the scenario ids in `conformance/core-unit.md`.

## 8. Docker integration contract

- `docker/compose.yml` runs the real service (image tag = stack catalog) plus a one-shot `bootstrap`
  service that prepares it (init/unseal, users, tokens, streams) and writes credentials to a shared
  volume `/bootstrap/env` (a `KEY=value` file). Health checks gate every dependency.
- One `test-<lang>` service per language (profile `<lang>`), built from `docker/Dockerfile.<lang>`
  with the repo root as context. The Dockerfile **packs** the package (npm tarball, wheel, `cargo
  package` / path dependency, Go module via `replace` in a consumer module, `mvn install` to the
  local repository) and installs it into a separate consumer project that holds the integration
  tests and the conformance runner — the integration suite imports the package the way a user does.
- No host ports are published. Run: `docker compose -p <key>-<lang>-<rand> --profile <lang> run
  --rm test-<lang>`, then always `docker compose -p … down -v` (the root Makefile does this with a
  trap).
- Integration tests read `/bootstrap/env` plus `GROW_<KEY_UPPER>_URL=http://<service>:<port>`.
- Every public function of the package is called at least once against the real service with a
  round-trip assertion (write → read back, send → query back). Functions the emulator/service cannot
  serve are listed in `docs/compatibility.md` with the reason and covered by unit tests.
