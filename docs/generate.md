# Generate a repository

sdk-kit is a Python ≥ 3.10 tool with no runtime dependencies. Run it from a checkout:

```sh
git clone https://github.com/grow-codes-packages/sdk-kit
cd sdk-kit
bin/sdk-kit list                       # services of spec/services.json (+ demo)
bin/sdk-kit new openbao --dest ../openbao
```

## Commands

| Command | What it does |
| - | - |
| `sdk-kit new <key> [--dest DIR] [--categories …] [--service-json FILE] [--package-version V] [--force]` | renders the template for a service into a new repository |
| `sdk-kit sync [--dest DIR] [--categories …] [--dry-run] [--force]` | refreshes every generated file (header `Generated by sdk-kit`); locally modified generated files are skipped unless `--force`; a header-less copy of a file the template now generates is adopted when it is unchanged since sdk-kit wrote it |
| `sdk-kit check [--dest DIR] [--key KEY]` | verifies a repository: manifest, required files, workflows calling sdk-kit, README badges, no template tokens left |
| `sdk-kit list` | lists the catalog |

`sdk-kit new demo` renders the **demo** service (all three categories) together with the demo
server in `demo/`; sdk-kit's CI runs the full pipeline of every language on it.

## What the generator does

1. Copies `template/common/**` to the repository root, `template/<lang>/**` to `<lang>/`,
   `template/docker/Dockerfile.<lang>` to `docker/`, `template/examples/<lang>/**` to
   `examples/<lang>/` and `conformance/` verbatim.
2. Replaces the [tokens](spec.md#0-template-tokens-and-generated-code) (`__KEY__`, `__SERVICE__`,
   `__PKG__`, …) in contents and paths.
3. Keeps `@sdk-kit:if <category>` … `@sdk-kit:endif` blocks only for the service's categories and
   drops category paths (`secrets/`, `logging_*.go`, `docs/tracing.md`, …) it does not have.
4. Records the sdk-kit version and a SHA-256 per generated file in `.sdk-kit.json`, so `sync` can
   tell local edits from template changes. The hash leaves out the bodies of keep regions.

## Keep regions

A generated file can hand parts of itself to the service repository:

```markdown
<!-- @sdk-kit:keep service-settings -->
| `token` — API token (secret) | none | `GROW___KEY_UPPER___TOKEN` |
<!-- @sdk-kit:endkeep -->
```

The marker lines use any `@sdk-kit:if` comment style (`//`, `#`, `<!--`, `/*`, `--`) and stay in the
rendered file; text after the name is a description. `new` writes the template's body; `sync`
re-renders the file and puts back the repository's body of every region with the same name.
Editing a region body therefore never blocks a sync, while an edit outside the regions still does.

| Situation on `sync` | Result |
| - | - |
| region body edited in the repo | kept; the rest of the file is updated |
| template adds a region the repo file does not have yet | template default body |
| template no longer has a region that holds content in the repo | file skipped (`SKIPPED (keep region …)`, exit 1); `--force` drops the content |
| repo file has no markers yet and is unmodified | updated, regions get the template defaults |
| repo file has no markers and is locally modified | skipped as locally modified (as before) |

Regions in the template today: `docs/configuration.md` (`service-settings`, `examples`),
`docs/client.md` (`functions`, `examples`, `service`), `docs/troubleshooting.md` (`connect`,
`authentication`, `service`), `AGENTS.md` (`service-specifics`) and `java/pom.xml` (`description`, `properties`,
`dependency-management`, `dependencies`, `compiler-args`, `plugins`). Malformed markers (unclosed,
nested, duplicate names) fail rendering, and `sdk-kit check` reports them in generated files.

## After generating

```sh
cd ../openbao
make deps build test        # all languages (LANGS="go python" for a subset)
make coverage               # coverage gates, writes <lang>/coverage/summary.json
make test-docker LANGS=go   # integration tests against the real service
make docs-site              # documentation site (pip install -r docs/requirements.txt)
```

Then implement the service: the client and config skeletons, the service modules, the category
primitives (for example the five secrets primitives), `docs/functions.md`,
`docs/compatibility.md`, the README function overview and the agent skill.

## Keeping repositories current

1. Change the template in sdk-kit and release it (see [Releasing sdk-kit](releasing.md)).
2. In each service repository run `sdk-kit sync`, review the diff and open a pull request.

The `check` job of every repository's CI runs `sdk-kit check` and reports (without failing) when
`sdk-kit sync --dry-run` would change files.
