# sdk-kit

[![License](https://img.shields.io/badge/license-Apache--2.0-blue)](LICENSE)
[![Grow Codes](https://img.shields.io/badge/Grow%20Codes-grow.codes-2ea44f)](https://grow.codes)

`sdk-kit` generates and maintains the Grow Codes open-source service SDK repositories in
[grow-codes-packages](https://github.com/grow-codes-packages). Every repository ships the same API
for one service (OpenBao, Vault, Loki, Jaeger, …) in **TypeScript, Rust, Go, Python and Java**,
built from one shared template so that every service and every language behaves the same way.

- `spec/SPEC.md` — the contract: names, defaults, error codes, environment variables, category
  interfaces (secrets, logging, tracing), template tokens and the Docker integration contract.
- `spec/services.json` — the 17 services and their token values.
- `template/` — what is copied into a service repository.
- `conformance/` — shared conformance scenarios, copied into every repository.
- `sdk_kit/` — the generator (Python ≥ 3.10, standard library only).
- `demo/` — a small demo server used by `sdk-kit new demo` and the Docker demo scenario.

## Install

```sh
# from a checkout, no installation needed
bin/sdk-kit --help

# or as a tool
pipx install git+https://github.com/grow-codes-packages/sdk-kit
```

The wheel bundles `template/`, `conformance/`, `spec/` and `demo/`, so an installed `sdk-kit`
works without a checkout. `--kit-root DIR` points it at another checkout.

## Commands

```sh
sdk-kit list                                   # the services of spec/services.json (+ demo)
sdk-kit new openbao --dest ../openbao          # generate a repository
sdk-kit new demo --dest /tmp/demo              # the demo service: all three categories
sdk-kit new my-svc --service-json svc.json     # a service that is not in the catalog
sdk-kit new loki --categories logging          # override the categories
sdk-kit sync --dest ../openbao                 # refresh the sdk-kit files of a repository
sdk-kit sync --dest ../openbao --dry-run       # show what sync would change
sdk-kit check --dest ../openbao                # verify required files (used by CI)
```

### `new`

Copies the template into the destination and replaces the SPEC §0 tokens (`__KEY__`,
`__KEY_SNAKE__`, `__KEY_UPPER__`, `__PKG__`, `__SERVICE__`, `__SERVICE_LOWER__`, `__DISPLAY__`,
`__VENDOR__`, `__UPSTREAM_LICENSE__`, `__IMAGE__`, `__PORT__`, `__VERSION__`,
`__SDK_KIT_VERSION__`, `__CATEGORIES__`; plus `__ENV__`, the vendor environment variables, for
docs) in file contents and paths.

| Source | Destination |
| - | - |
| `template/common/**` | `<repo>/` |
| `template/<lang>/**` | `<repo>/<lang>/` |
| `template/docker/**` | `<repo>/docker/` |
| `template/examples/<lang>/**` | `<repo>/examples/<lang>/` |
| `conformance/**` | `<repo>/conformance/` (verbatim) |
| `demo/**` (demo only) | `<repo>/demo/` (verbatim) |

- **Category blocks**: lines between `@sdk-kit:if <category>` (or `@sdk-kit:if any(a,b)`) and
  `@sdk-kit:endif` are kept only when the service has the category. Markers may use `//`, `#`,
  `<!-- -->`, `/* */` or `--` comments and are always removed. Blocks do not nest; a malformed
  marker or unknown category is an error that names the file and line.
- **Category paths**: a path with a segment matching `^_?(secrets|logging|tracing|auth)([_.-]|$)` belongs
  to that category; other paths are listed in `template.json` of the template folder
  (`{"categories": {"logging": ["zapadapter"]}}`, exact path, folder prefix or glob). Paths of
  missing categories are dropped. `template.json` itself is not copied.
- Executable bits are kept, binary files (NUL byte or not UTF-8) are copied untouched, symlinks are
  recreated, and `CLAUDE.md` is always a symlink to `AGENTS.md`.
- Build output in the template (`node_modules`, `target`, `dist`, `coverage`, `__pycache__`, …) is
  skipped.
- `.sdk-kit.json` records the sdk-kit version, key, categories, service values and every written
  file with its SHA-256 and whether it is generated.
- A non-empty destination is refused unless `--force` (a directory with only `.git` counts as
  empty).

### `sync`

Re-renders the template with the recorded service and categories and:

- overwrites files that carry the `Generated by sdk-kit` header (first 10 lines) and the
  `conformance/` folder, and recreates the `CLAUDE.md` symlink;
- skips and reports generated files that were changed locally (SHA-256 differs from
  `.sdk-kit.json`) unless `--force`; exit code 1 when something was skipped;
- leaves a file alone for good once its header was removed (the service took it over);
- never touches service-owned files (no header); a service-owned file that is new in the template
  is created once, a deleted one is not recreated;
- removes generated files that are no longer rendered (for example after `--categories`).

### `check`

Fails (exit 1) when a repository misses something sdk-kit requires: `LICENSE` (Apache-2.0),
`NOTICE`, `README.md` with the CI, coverage (5 languages), licence, docs and Grow Codes badges,
`AGENTS.md` + `CLAUDE.md` symlink, `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, the skill
file, the five language folders with their `Makefile`, `docker/compose.yml` and the five
Dockerfiles, `.github/workflows/{ci,release,docs}.yml` with at least one workflow calling sdk-kit,
`conformance/VERSION`, the release-please files, and no template token left anywhere.

## Development

```sh
make test        # pytest, coverage gate >= 90 % lines and >= 90 % branches
make lint        # ruff check, ruff format --check, mypy --strict
make demo        # render the demo repository into build/demo
make check-all   # render every service into build/<key> and run sdk-kit check on each
```

`make` creates a virtual environment in `.venv` (override with `VENV=…`). See
[AGENTS.md](AGENTS.md) for the rules of this repository and [CONTRIBUTING.md](CONTRIBUTING.md).
