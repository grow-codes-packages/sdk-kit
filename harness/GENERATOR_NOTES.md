# Generator rules for the Docker harness

`tests/render_repo.py` implements these rules for the harness tests; keep both in sync.

## 1. Always

- `template/common/docker/**` → `<repo>/docker/**` with tokens replaced (normal template rule).
  Files with the "Generated by sdk-kit" header (`compose.yml`, `bootstrap/lib.sh`, `harness/*.sh`)
  are synced; `compose.service.yml`, `bootstrap/bootstrap.sh` and `bootstrap/README.md` are
  generated once and then belong to the repository.
- Keep the executable bit of `docker/harness/*.sh` and `docker/bootstrap/*.sh`.
- `__PORT__` must be a plain port number in `docker/` (it builds `GROW_<KEY>_URL=http://service:__PORT__`).
  `services.json` has non-numeric values for three keys; use the leading digits, and these overrides:

  | Key | `__PORT__` in docker/ | why |
  | - | - | - |
  | `aws-secrets-manager`, `aws-cloudwatch-logs` | `5000` | catalog says `5000 (moto)` |
  | `datadog-logs` | `80` | catalog says `80 (fakeintake)` |
  | `better-stack-logs` | `8080` | catalog says `—`; stub ingest port |
  | `demo` | `8080` | demo server |

## 2. Docker variants (service-owned files replaced at generation time)

| Key | Copy from sdk-kit | To |
| - | - | - |
| `demo` | `demo/server.py`, `demo/Dockerfile`, `demo/.dockerignore` (not `demo/tests/`) | `docker/demo/` |
| | `demo/compose.service.yml` | `docker/compose.service.yml` |
| | `demo/bootstrap/bootstrap.sh` | `docker/bootstrap/bootstrap.sh` |
| `aws-secrets-manager`, `aws-cloudwatch-logs` | `harness/moto/compose.service.yml` | `docker/compose.service.yml` |
| | `harness/moto/bootstrap.py` | `docker/bootstrap/bootstrap.py` |
| `datadog-logs` | `harness/fakeintake/compose.service.yml` | `docker/compose.service.yml` |
| | `harness/fakeintake/bootstrap.sh` | `docker/bootstrap/bootstrap.sh` |
| | `harness/fakeintake/fakeintake.py` | `docker/harness/fakeintake.py` |
| `better-stack-logs` | `harness/betterstack-stub/{stub,sql,otlp,msgpack_decode}.py`, `Dockerfile`, `.dockerignore` | `docker/betterstack-stub/` |
| | `harness/betterstack-stub/compose.service.yml` | `docker/compose.service.yml` |
| | `harness/betterstack-stub/bootstrap.sh` | `docker/bootstrap/bootstrap.sh` |

The `demo` row is what `sdk_kit/render.py` already does (raw copy of `demo/` minus `tests/`, then
`_DEMO_OVERRIDES`). The other rows are recommended so the service agents start from a working
Docker setup; the files are service-owned afterwards (no generated header), so `sdk-kit sync`
never overwrites them. Not listed: `datadog-apm` (adds a `datadog/agent` next to fakeintake — see
`harness/fakeintake/README.md`) and every service with a real image (the template placeholder uses
`__IMAGE__`).

## 3. Root Makefile

`make test-docker` may simply call, per language:

```sh
SDK_DOCKER_LOCK_DIR=$(SDK_DOCKER_LOCK_DIR) docker/harness/compose-run.sh -l auto <lang>
```

(`-l none` when the lock directory does not exist). It gives the unique project name, the
`down -v` trap, failure logs and per-run test image tags in one place.
